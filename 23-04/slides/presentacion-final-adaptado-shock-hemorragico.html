EXORDIO · Gancho

EL PROBLEMA

¿Qué problema existe en el mundo médico?

Shock Hemorrágico Postoperatorio

El shock hemorrágico es una emergencia médica en la que el paciente pierde suficiente sangre para comprometer la perfusión de órganos vitales, llevando a hipoxia tisular, falla multiorgánica y potencialmente la muerte.


Mortalidad: Representa una de las principales causas de muerte prevenible en cirugía mayor, con tasas de mortalidad que alcanzan el 30-40% cuando no se detecta tempranamente.

Detección Tardía

  • Dependencia de experiencia médica: Variabilidad en interpretación clínica, sesgos cognitivos
  • Protocolos no actualizados: Enfoque reactivo en lugar de predictivo
  • Falta de personalización: No se consideran factores de riesgo individuales del paciente
  • Limitaciones humanas: Fatiga, dificultad para detectar cambios sutiles en signos vitales

Consecuencias

Aumento de mortalidad postoperatoria, mayor necesidad de transfusiones sanguíneas, complicaciones como falla multiorgánica, daño renal y cerebral, incremento de costos hospitalarios y saturación de UCI.

2
EXORDIO · Tesis

¿POR QUÉ ES IMPORTANTE?

La necesidad de un enfoque predictivo y personalizado

Salvar Vidas

La detección temprana permite intervención inmediata antes de que se desarrolle falla multiorgánica irreversible, reduciendo significativamente la mortalidad postoperatoria.

Optimizar Recursos

Preparación anticipada de hemoderivados, personal médico y equipos, reduciendo transfusiones reactivas innecesarias y uso ineficiente de sangre.

Reducir Complicaciones

Prevenir daño orgánico por hipoperfusión prolongada (insuficiencia renal aguda, daño cerebral, necrosis intestinal), acortando tiempos de recuperación.

Apoyo Clínico Objetivo

Complementar la experiencia médica con herramientas predictivas basadas en inteligencia artificial, estandarizando criterios diagnósticos y reduciendo sesgos.

Nuestra Propuesta

Desarrollar un modelo de inteligencia artificial que permita la predicción temprana del riesgo de shock hemorrágico, integrando datos preoperatorios e intraoperatorios.

NARRATIO · Metodología

ENFOQUE METODOLÓGICO

CRISP-DM + TRIPOD para desarrollo riguroso

CRISP-DM

Cross-Industry Standard Process for Data Mining — Marco iterativo de 6 fases:

  • Business Understanding: Definición del problema clínico
  • Data Understanding: Exploración del dataset
  • Data Preparation: Limpieza y transformación
  • Modeling: Entrenamiento de algoritmos ML
  • Evaluation: Validación con métricas clínicas
  • Deployment: Preparación para integración

TRIPOD

Transparent Reporting of a multivariable prediction model for Individual Prognosis Or Diagnosis — Guía para modelos predictivos en medicina:

  • Transparencia en definición de variables
  • Manejo riguroso de datos faltantes
  • Validación interna con CV estratificada
  • Reporte completo de métricas diagnósticas
  • Análisis de calibración del modelo

Enfoque Iterativo de 4 Fases

Fase 1: Evaluación baseline con 7 algoritmos por defecto · Fase 2: Feature engineering con conocimiento médico · Fase 3: Selección del modelo champion · Fase 4: Optimización de hiperparámetros y umbral de decisión

NARRATIO · Tecnología

INTERPRETABILIDAD: SHAP

SHapley Additive exPlanations — Transparencia del modelo

¿Qué es SHAP?

Técnica basada en teoría de juegos que calcula la contribución individual de cada variable a la predicción del modelo.


Usa valores de Shapley para repartir la "responsabilidad" de la predicción entre todas las variables, comparando qué tanto cambia el resultado si una característica se incluye o excluye.

¿Por qué es importante?

  • Validación Clínica: Permite a los médicos ver exactamente qué factores aumentan o disminuyen el riesgo de shock
  • Transparencia: Transforma modelos de "caja negra" en sistemas interpretables y auditables
  • Confianza: Las decisiones del algoritmo tienen sentido médico verificable

Implementación

Importancia Global: Qué variables pesan más en promedio (EDAD: 42.9%, HB_PREQX: 32.8%)
Explicaciones Locales: Por qué un paciente específico fue clasificado en riesgo

NARRATIO · Fase 4

ANÁLISIS DE UMBRAL

Trade-off Sensibilidad vs Especificidad

Puntos Críticos

  • Threshold = 0.0: Sensibilidad = 1.0, Especificidad ≈ 0 (todos positivos, sobrecarga clínica)
  • Threshold = 0.3-0.4: Máximo F1-Score (~0.52), balance óptimo
  • Threshold = 0.5: Punto equilibrio teórico estándar

Recomendación Valle del Lili

Threshold ≈ 0.30-0.35

  • Recall ≥ 80% (detectar 326 de 377 casos de shock)
  • ~51 alertas por 131 pacientes (40% tasa activación)
  • Equipo valida clínicamente con lactato, déficit base

DEMOSTRATIO · Implementación

RECOMENDACIONES PARA FVL

  1. Algoritmo Seleccionado: XGBoost como modelo principal, CatBoost como alternativa validada de respaldo.
  2. Threshold Operativo: 0.30-0.35 para maximizar sensibilidad con especificidad clínicamente aceptable.
  3. Protocolo de Uso Escalonado:
    • Probabilidad ≥ 0.40: Activar protocolo shock hemorrágico completo (anestesiólogo, preparar transfusión)
    • Probabilidad 0.30-0.40: Intensificar monitoreo, confirmación con marcadores laborales (lactato, déficit base)
    • Probabilidad < 0.30: Vigilancia estándar postoperatoria
  4. Validación Prospectiva: Estudio piloto con 50-100 casos quirúrgicos reales antes de implementación clínica completa.
  5. Reentrenamiento Periódico: Cada 500-1000 casos nuevos para recalibración y detección de concept drift.

EPÍLOGO · Conclusiones

CONCLUSIONES

Limitaciones Identificadas

  • Dataset insuficiente: Las variables estáticas preoperatorias disponibles (comorbilidades, edad, hemoglobina) no son suficientes para predicción robusta del shock hemorrágico con estándares clínicos requeridos.
  • AUC-ROC 0.639: Moderado. Aunque inferior al ideal (>0.80), el Recall de 86.5% cumple el objetivo clínico prioritario.
  • Variables temporales faltantes: Se necesitan datos continuos pre, intra y postquirúrgicos (signos vitales en tiempo real, tendencias de PA, FC, SpO2).

Logro Real del Proyecto

  • Arquitectura robusta y parametrizable: Framework de experimentación validado con múltiples algoritmos (7 modelos), 4 fases iterativas, metodologías estandarizadas (CRISP-DM, TRIPOD).
  • Pipeline escalable: Sistema modular que permite fácil integración de nuevas variables y algoritmos sin rediseño completo.
  • Base sólida: Infraestructura lista para futuras iteraciones cuando se obtengan datos temporales y multivariados.

Conclusión Principal

El dataset actual no permite predicción clínicamente robusta del shock hemorrágico. Sin embargo, hemos desarrollado una arquitectura de experimentación robusta, parametrizable y escalable que constituye la base fundamental para futuros desarrollos con datos más completos.

EPÍLOGO · Trabajo Futuro

TRABAJO FUTURO Y VALOR GENERADO

Próximos pasos y el verdadero logro de este proyecto

Requisitos para Predicción Robusta

  • Variables temporales continuas: Integrar series temporales de signos vitales (FC, PA, SpO2, temperatura) en tiempo real durante cirugía
  • Datos tri-fase: Prequirúrgicos + Intraoperatorios + Postoperatorios en ventana temporal completa
  • Modelos de series temporales: LSTM, Transformers o arquitecturas híbridas para capturar evolución dinámica
  • Dataset ampliado: > 5000 casos con mayor diversidad quirúrgica

Valor de la Arquitectura Desarrollada

  • Framework robusto y parametrizable: Pipeline modular con 7 algoritmos, 4 fases de experimentación, métricas estandarizadas
  • Escalabilidad garantizada: Fácil integración de nuevas variables y modelos sin rediseño estructural
  • Metodologías validadas: CRISP-DM + TRIPOD aseguran rigor científico
  • Base fundamental: Infraestructura lista para implementación cuando se obtengan datos adecuados

Valor Real del Proyecto

No logramos un sistema de predicción clínico operacional (el dataset no lo permite), pero construimos la arquitectura robusta y metodología rigurosa que permitirá lograrlo cuando se cuente con datos temporales continuos. Este es un proyecto de infraestructura que sienta las bases para futuros desarrollos exitosos.
